# Contributing to Realism Influ

Contributions can include research summaries, source reviews, prompt modules, camera profiles, lighting recipes, evaluation reports, and corrections.

## Before contributing

- Read the research methodology and data/rights policy.
- Search for an existing asset before adding a duplicate.
- Identify whether the contribution is evidence, practitioner advice, a community observation, or a hypothesis.
- Distinguish observation from assumption.

## Source review

Include title, author/creator, date, venue/domain, URL, access date, evidence class, original summary, relevant findings and limitations, related assets, and rights notes. Do not paste full articles, paid prompt packs, or large copyrighted excerpts.

## Prompt asset review

Include stable ID, intended task/scenario, prompt fragment, variables, expected behavior, compatible model/version if known, source IDs, status, known failures, and limitations.

## Experiment review

Include full prompt and settings, all trials, seed controllability, evaluation method, and failures. Keep aesthetics separate from realism. Avoid unsupported “best prompt” or “guaranteed” claims. Label generated examples as synthetic when sharing.

## Camera profile review

Verify device and lens specifications against manufacturer documentation. Keep hardware specifications separate from visual targets. Never invent EXIF metadata.

## Style

Use clear Markdown headings, concise tables, stable relative links, original explanations, dates and versions when behavior may change, and a limitations section for substantive summaries.

## Pull request checklist

- [ ] Links work and point to primary sources where possible.
- [ ] Source type and confidence are explicit.
- [ ] No unsupported claims.
- [ ] Rights and licenses are recorded.
- [ ] Prompt is tested or marked untested.
- [ ] Settings and failures are documented.
- [ ] Related indexes and links are updated.
